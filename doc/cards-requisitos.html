Importância: Essencial Importante Desejável
RF1Essencial

Cadastro com especificações técnicas

Formulário para registrar um produto com modelo, armazenamento, RAM, slots de expansão, marcas de uso e saúde da bateria, se utilizar checkbox melhor ainda etc.

Como validar

Submeter um cadastro completo e confirmar que todos os campos foram gravados no banco.

Atenção

Definir campos obrigatórios vs opcionais — exemplo modelo é obrigatório.

RF2Essencial

Anexo de fotos

Permitir anexar uma ou mais fotos ao produto durante o cadastro.

Como validar

Anexar imagens, salvar e confirmar que aparecem na tela de consulta.

Atenção

Definir formatos aceitos (jpg/png), tamanho máximo e quantidade de fotos por produto.

RF3Essencial

Persistência dos dados

Gravar os dados do produto de forma durável no SQLite.

Como validar

Reiniciar a aplicação e verificar que os produtos cadastrados continuam disponíveis.

Atenção

O SQLite é arquivo único — guardar em volume Docker para não perder os dados ao recriar o container.

RF4Essencial

Geração de QR Code

Ao salvar, gerar um QR Code apontando para a URL única do produto: /produtos/:id.

Como validar

Escanear o QR com o celular e confirmar que abre a tela de consulta correta.

Atenção

Tudo é local: o QR deve usar o IP da máquina na rede (não localhost), e quem escaneia precisa estar na mesma rede.

RF5Essencial

Tela de consulta do produto

Página que exibe os dados e as fotos de um produto a partir do seu ID/URL.

Como validar

Acessar /produtos/:id de um produto existente e ver todas as infos; um ID inexistente mostra erro amigável.

Atenção

Consulta aberta nesta POC (sem login). Cuidar do estado de "produto não encontrado".

RF6Importante

QR Code para impressão

Disponibilizar o QR Code em PNG/SVG para imprimir como etiqueta do produto.

Como validar

Baixar o arquivo, imprimir e conferir que o scan continua legível após impresso.

Atenção

SVG escala melhor na impressão; definir tamanho mínimo da etiqueta para o scan funcionar.

RF7Essencial

Validação de dados na API

A API valida tipos e campos obrigatórios antes de gravar o produto.

Como validar

Enviar um payload inválido via POST e receber erro 4xx com mensagem clara.

Atenção

Alinhar as regras de validação entre front e back para não divergirem.

RF8 · bônusDesejável

Pipeline de imagens

Armazenar as imagens fora do banco e servi-las (conexão FTP + infra).

Como validar

Subir uma imagem e acessá-la pela URL servida, confirmando que persiste.

Atenção

Escopo stretch. Para uma POC local, salvar a imagem direto no volume já resolve — o FTP adiciona complexidade.

RNF1Importante

Arquitetura monorepo

Front-end e back-end organizados num único repositório.

Como validar

Clonar o repositório e rodar front + back a partir dele, seguindo o setup documentado.

Atenção

Definir estrutura de pastas (ex.: /frontend, /backend) e scripts de execução.

RNF2Importante

Containerização com Docker

Aplicação executável via Docker / docker-compose.

Como validar

Um docker compose up sobe o ambiente completo e funcional.

Atenção

Persistir o arquivo SQLite e as imagens em volume para não perdê-los ao recriar o container.

RNF3Essencial

Schema padronizado e IDs únicos

Modelo de dados com campos padronizados e um identificador único por produto.

Como validar

Cadastrar dois produtos e confirmar que recebem IDs distintos e sem colisão.

Atenção

Autoincremento vs UUID. Para a POC, autoincremento já basta; UUID deixa a URL menos previsível, se importar.

RNF4Importante

Deploy local e teste end-to-end

Ambiente hospedado localmente, com o fluxo completo testado ponta a ponta.

Como validar

Rodar o fluxo cadastro → salvar → gerar QR → escanear → consultar sem falhas.

Atenção

Combinar a "definição de pronto" (DoD) do fluxo antes de testar.
